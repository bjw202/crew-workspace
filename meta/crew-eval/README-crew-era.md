# meta — 사람이 읽는 안내

이 폴더는 **crew 가 값을 하는지 재는 자리**입니다.
crew 는 봇 다섯이 채팅방에서 연구 과제를 잇는 실험이고, 여기는 그 실험을 밖에서 보는 자리입니다.

과제 분석은 여기서 하지 않습니다. 그건 봇이 합니다.

---

## 1. 왜 자리를 나눴나

**만드는 사람과 채점하는 사람이 같으면 채점이 무너지기 때문**입니다.

시험 문제를 낸 사람이 자기 답안지를 채점하는 것과 같습니다.
crew 안에서도 같은 원리를 씁니다 — orchestrator 는 결과물을 읽지 않고, 검토는 다른 봇이 합니다.

그 원리를 한 층 위에도 적용한 것이 이 폴더입니다.

그리고 자리를 나눈 데는 실무적인 이유가 하나 더 있습니다.
`CLAUDE.md` 는 **위쪽 폴더까지 거슬러 올라가며 읽힙니다.**
그래서 `crew/` 안에 `CLAUDE.md` 를 두면 봇 다섯이 그것을 함께 읽습니다.
`meta/` 는 `crew/` 의 **형제**라서 봇이 절대 못 봅니다.

    crew-workspace/
      ├── crew/      ← 봇이 삽니다. CLAUDE.md 를 두지 않습니다
      ├── meta/      ← 여기. 봇은 못 봅니다
      ├── rooms/
      ├── knowledge/
      └── minidiscord/

## 2. 세션 여는 법

    cd <작업판>/crew-workspace/meta
    claude --add-dir ../crew --add-dir ../rooms --add-dir ../minidiscord

`--add-dir` 은 "이 폴더도 읽고 쓸 수 있게 해 줘"라는 뜻입니다.
세션은 `meta/` 에 앉아 있으면서 `crew/` 를 직접 다룹니다.
**crew 에서 세션을 따로 띄울 필요가 없습니다.**

다만 `../minidiscord` 는 **읽으려고** 붙인 것입니다.
방의 숫자를 세고(`server/data/minidiscord.db`), 증상의 원인을 읽는 데 씁니다.
채팅 서버 코드를 고칠 일이 생기면 **그 저장소에서 세션을 따로 띄우십시오** —
거기에는 자기 규칙과 시험, 커밋 훅이 있고 그것이 실제로 오류를 잡습니다.
진단은 여기서, 수정은 거기서.

---

## 3. 한 바퀴 — 회차가 닫히면 이 순서로

    ① 봇이 회고를 쓰고 제안을 PR 로 올린다        ← 봇이 합니다
    ② 사람이 그 PR 을 머지하거나 닫는다            ← GitHub 에서
    ③ meta 가 계측한다                            ← 세션이 합니다
    ④ meta 가 예측을 notes/ 에 숫자로 적는다       ← 세션이 합니다
    ⑤ meta 가 규칙을 고쳐 PR 을 올린다             ← 세션이 합니다
    ⑥ 사람이 머지한다                             ← GitHub 에서
    ⑦ 봇 끄기 → pull → 봇 켜기 → 방에 알린다      ← 사람이 합니다

### 왜 ①이 ⑤보다 먼저인가

봇도 PR 을 올리고 meta 도 PR 을 올립니다. 같은 저장소입니다.
**봇 것을 먼저 처리해야** meta 가 최신 상태에서 브랜치를 뜹니다.
순서가 뒤바뀌면 `divergent branches` 라는 오류가 납니다. 2026-09-09 에 실제로 났습니다.

### 왜 ④가 ⑤보다 먼저인가

고친 다음에 기준을 정하면 **언제나 성공**이 됩니다.

다이어트로 치면 이렇습니다.

    나쁜 순서 : 살을 뺀다 → 잰다 → "이 정도면 성공이지"
    좋은 순서 : "3kg 뺀다"를 적는다 → 살을 뺀다 → 잰다 → 3kg 인가?

예측은 `notes/` 에 적습니다. **crew 안에 적으면 봇이 채점 기준을 미리 봅니다.**

## 4. 사람이 직접 치는 명령은 둘뿐입니다

나머지는 세션이 하거나 GitHub 에서 버튼을 누릅니다.

### 세션 열 때

    cd <작업판>/crew-workspace/meta
    claude --add-dir ../crew --add-dir ../rooms --add-dir ../minidiscord

### 머지 뒤 봇에게 전달할 때

    # 1) 봇 터미널 다섯에서 각각 Ctrl+C 두 번 (또는 /exit)
    # 2) 껐는지 확인
    pgrep -f "mcp-config .mcp.json" | wc -l      # 0 이 나와야 합니다

    # 3) 받기
    cd <작업판>/crew-workspace/crew
    git pull

    # 4) 봇 터미널 다섯에서 원래 명령을 다시 칩니다
    #    명령이 기억 안 나면: node setup.js  → 다섯 줄을 다시 찍어 줍니다

**minidiscord 서버는 끄지 않습니다.** 끄면 방이 닫힙니다.

## 5. GitHub 화면 안내

### PR 을 열면 탭이 넷 보입니다

    Conversation   Commits   Checks   Files changed

- **Conversation** — 설명. 처음 열리는 화면입니다
- **Files changed** — 실제로 바뀌는 글자. **빨강이 지워질 글, 초록이 들어올 글**입니다

### 머지하기

`Conversation` 아래쪽 초록 버튼 **`Merge pull request`** → **`Confirm merge`**.

버튼 옆 작은 화살표(▾)는 그냥 두십시오. 기본값이 맞습니다.

머지 뒤 나오는 회색 `Delete branch` 는 눌러도 안전합니다.

### 초록 버튼이 회색이면

브랜치 보호에서 "승인 1개 필요"가 켜진 것입니다.
`Files changed` → 오른쪽 위 `Review changes` → `Approve` → `Submit review` 를 먼저 하시면 살아납니다.

### 조금만 고치면 될 때

반려하고 다시 시킬 필요 없습니다.
`Files changed` 에서 줄 옆의 **연필 아이콘**을 눌러 그 자리에서 고치고 커밋하면 됩니다.

## 6. 막힐 때

### `divergent branches ... Need to specify how to reconcile`

**받는 사이에 봇이 커밋을 했다는 뜻**입니다. 고장이 아닙니다.

    git config pull.rebase false     # 이 폴더에 한 번만
    git pull

앞으로는 안 물어봅니다.

### 편집기(vim)가 열리고 `~` 만 잔뜩 보인다

git 이 "합쳤음" 기록에 설명을 적으라고 편집기를 연 것입니다.
**git 이 이미 다 써 놨습니다.** 저장만 하면 됩니다.

    :wq   그리고 Enter

`:` 을 쳐도 아래에 아무것도 안 나오면 `Esc` 를 한 번 누르고 다시 치십시오.

### `! [remote rejected] ... protected branch`

**고장이 아닙니다.** main 에 직접 못 올리게 막아 둔 것이 제대로 작동한 것입니다.
브랜치를 떠서 PR 로 올리면 됩니다. 세션이 알아서 합니다.

### 방 화면에서 옛 대화가 안 보인다

새로고침해 보십시오. 데이터는 서버에 다 있습니다.
그래도 안 보이면 봇에게 물으십시오 — 봇은 화면이 아니라 서버에서 직접 읽습니다.

## 7. `notes/` 에 무엇을 적나

**이번 회차의 예측**을 적습니다. crew 안에 적지 않습니다.

숫자로만 적습니다.

    보고 글자 수 중앙값        1280 →  500 이하
    6줄 위반율                  79% →   30% 이하
    자기 계측 줄이 붙은 비율      0% →  100%
    자기 계측 값과 실측의 어긋남   미측정 →   5% 이내
    작업당 관여 봇 수            미측정 →  기록됨

"짧아진다" 같은 말로 적으면 나중에 봐주게 됩니다.

회차가 끝나고 판정까지 마치면, 결과를 `../crew/EVOLUTION.md` 로 옮깁니다.
**목표는 밖에, 결과는 안에.**
