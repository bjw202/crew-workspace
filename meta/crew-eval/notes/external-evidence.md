# 바깥 근거 — 우리 결론이 발표된 연구와 어떻게 맞나 (2026-09-09)

meta 세션이 조사했다. 우리가 잰 것과 문헌이 같은 방향인지, 그리고 **우리가 놓친 조건**이 있는지 봤다.

## 요약 셋

1. **다중 에이전트가 단일보다 나은 경우는 드물고, 원인은 과제 난이도가 아니라 조율 비용이다.** 우리 실측과 같다.
2. **검토를 다른 문맥에서 하는 것은 확립된 결과다.** 우리가 옳게 한 부분이다.
3. **다중이 이기는 조건이 따로 있고, 회차 4 는 그 조건이 아니었다.** 이것이 진짜 진단이다.

---

## 1. MAST — 원문으로 확인함 (arXiv 2503.13657)

UC Berkeley·IBM. 논문이 **직접 말한 것**만 적는다.

| | |
|---|---|
| 분석한 실행 트레이스 | **1,642개** |
| 프레임워크 | **7개** (ChatDev · MetaGPT · HyperAgent · AppWorld · AG2 · Magentic-One · OpenManus) |
| 실패율 | **41% ~ 86.7%** |
| 성능 결론 | "다중 에이전트 시스템에 대한 열의에도, 널리 쓰이는 벤치마크에서 성능 향상은 **대체로 미미하다**" |

실패의 세 범주는 **명세 문제 · 에이전트 간 어긋남 · 검증 부실**이다.

**주의**: 2차 블로그들이 "42% / 37% / 21%"라는 범주별 비율을 인용하는데 **논문 원문에는 그 상위 범주 비율이 없다.** 그 숫자는 쓰지 마라.

**우리 것과 겹치는 자리**

- 에이전트 간 어긋남 → `SH2200-A-1190` 이 analyst·researcher 를 거쳐 reporter 에 못 닿았다 (재고 지뢰가 보고서에서 빠졌다)
- 검증 부실 → "도구 승인 78회 → 1회"를 한 세대 성과로 믿었는데 권한 모드 탓이었다

## 2. 검토는 다른 문맥에서 — 우리가 옳게 한 부분

문헌의 결론: **모형은 자기 결과물을 잘 승인한다.** 같은 문맥에 있으면 만들 때의 전제와 맹점을 공유해 못 본다.
1차 근거는 OpenAI 의 *LLM Critics Help Catch LLM Bugs* 다.

우리 실험이 그대로 재현했다.

    싱글 넷 (검토 없음)   PM 단독 대조군 오류가 그대로 남음
    검토 세션 ($1.69)     같은 오류 + 통계 과장 둘을 잡음

**이건 봇을 다섯 두는 것과 무관하다.** 문맥 하나만 따로 떼면 된다.

## 3. 다중이 이기는 조건 — 우리는 그게 아니었다

Anthropic 의 Research 기능은 단일 Claude Opus 4 대비 **90.2% 향상**, 대신 토큰 **약 15배**다.
그런데 통하는 조건이 명시돼 있다.

> **breadth-first** — 독립적인 갈래 여럿을 동시에 파야 하고, 정보 총량이 한 문맥에 안 들어가는 과제.
> 예: S&P 500 IT 기업 65곳의 이사회 명단 전부 찾기.

**회차 4 는 반대였다.** 자료 셋이 서로 이어지고, 물음이 하나고, 결론 하나 위에 다음이 서는 **순차형**이다.
문헌이 "다중이 지는 자리"라 말하는 바로 그 모양이다.

**그리고 crew 규칙에 이미 그 기준이 있다.** `bots/orchestrator/CLAUDE.md` 의
① "갈래가 둘 이상이라 따로 파야 한다" 가 곧 breadth-first 다.
회차 4 에서 그 조건은 **충족되지 않았고**, orchestrator 는 ③ "산출물이 여러 종류다"로 나눴다.
대조군 실험이 반증한 그 기준이다.

**문헌이 독립적으로 같은 결론에 온다 — ① 은 남기고 ③ 은 빼라.**

## 4. meta 절차 자체는 표준이었다

"고치기 전에 기준선을 정하고, 바꾼 뒤 회귀를 검사하고, **사후에 지표를 고르지 않는다**"는
에이전트 평가의 표준 권고다.

우리는 안 했을 때 실제로 틀렸다 — 회차 3 은 예측 없이 고쳤고 성과 주장 둘이 나중에 무너졌다.
회차 4 에 예측을 먼저 적고서야 판정이 섰다.

**봇 다섯보다 이 절차가 값을 했다.**

## 바꿀 질문

지금까지 **"봇을 몇 개 둘까"**를 물었다. 문헌과 실측이 같이 말하는 것은
**"이 과제가 어떤 모양인가"**를 먼저 물으라는 것이다.

| 과제 모양 | 구성 |
|---|---|
| 갈래 여럿이 서로 안 기대고 한 문맥에 안 들어감 (breadth-first) | 병렬 다중 — 15배 값을 낼 만하다 |
| 자료 하나, 결론 하나 위에 다음이 섬 (순차형) | 단일 + 다른 문맥의 검토 하나 |
| 기록 | 작업이 아니다. 회차 마감에 한 번 |

사람이 말한 "싱글로도, 직렬로도, 병렬로도 돌 수 있다"가 이것이다.
문헌이 그 직관을 뒷받침하고 **고를 기준까지 준다 — 갈래가 독립인가.**

## 인용의 신뢰도

- **원문 확인**: MAST (arXiv 2503.13657)
- **1차 자료**: OpenAI *LLM Critics Help Catch LLM Bugs* · Anthropic 엔지니어링 공개 자료(90.2% / 15배)
- **확인 못 함**: 검색에 걸린 2차 블로그의 수치들 — "2개만 써도 15~49% 손실", "80%의 경우 단일이 이긴다",
  "자기 검토가 31.7%를 놓친다". 방향은 일치하지만 **근거로 쓰지 마라.**

우리 판단은 우리가 직접 잰 값($135.50 대 $7.16 · 검토가 잡은 오류 셋) 위에 세우는 것이 맞다.
바깥 근거는 그 값이 이상한 값이 아니라는 확인이지 대체물이 아니다.
