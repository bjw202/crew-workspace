# 지금(v1) → 앞으로(v2) — 한 장으로 (2026-09-14 저녁, 사람 결정)

`DIRECTION-v2.md`(사람 말 · 영향 · 물음)의 결론이다. 사람이 물음 여섯에 "meta 추천을 수용한다" 고 답했고, 하나를 더 얹었다: **"디스코드 UI 디자인을 계승했으니 디자인을 잘 살려라."** cockpit 세션에 주는 것은 이 문서와 `instructions/D0-v2.md` 다. 예측 · 채점표는 주지 않는다.

## 한 줄
**속은 cockpit(SDK 로 봇 세션을 띄우고 붙드는 서버), 겉은 minidiscord(방 목록 · 메시지 · 작성기 · `@` 칩 · 첨부의 화면과 디자인 토큰). 방은 과제마다 하나이고 그 방에 전용 봇이 산다. files 방은 없다.**

## 그림
```
v1 (지금)                                          v2 (앞으로)

브라우저 ─ cockpit 자체 화면(채팅 · 조종석 · 파일 탭)     브라우저 ─ minidiscord 화면 그대로 + 오른쪽 접이식 조종석 판
   │                                                  │
cockpit 서버 ── 과제 = 봇 1 + 방 2(본방 · files)       cockpit 서버 ── 방 1 = 과제 1 = 봇 1 (방 만들기가 봇을 만든다)
   │ SDK query()                                      │ SDK query() (그대로)
Claude Code CLI + prodev 하네스                       Claude Code CLI + prodev 하네스 (방 하나 판으로 고침 11곳)
```

## 요구 — v1 의 R0~R8 에 더하는 여섯 (사람, 2026-09-14)
| # | 요구 | 출처 |
|---|---|---|
| **R9** | **화면은 minidiscord 를 계승한다.** `web/`(app.js · rich.js · style.css · index.html) 과 `design-tokens.css`(토큰 34) 를 옮기고, 방 목록 사이드바 · 아바타 메시지 · 작성기 한 덩어리 · 계정 바 · 본문 마크다운 · `@TO` `@CC` 칩 · `@` 자동완성 · 이미지 붙여넣기 · 끌어놓기 · 썸네일 · UTC 표기 · 히스토리 끝까지 · SSE 백필을 **그대로** 둔다. 디자인 토큰 값은 바꾸지 않는다 | 사람 "디자인을 잘 살려라" |
| **R10** | **방 하나 = 과제 하나 = 전용 봇 하나.** files 방은 없다. admin 이 방을 만들면 prodev 기반 봇(봇 폴더 · 과제 폴더 · 설정 두 장. 스킬 · 도우미 · CLAUDE.md 는 링크가 아니라 봇 폴더 위쪽 prodev 뿌리에서 CLI 가 스스로 읽는다 — 2026-09-15 D4 에서 바로잡음)과 세션 줄이 함께 생긴다 | 사람 3 · 4 |
| **R11** | **봇에게 가는 글은 `@TO(봇)` · `@CC(봇)` 이 있는 글뿐**(minidiscord 규칙). `@` 없는 글은 사람끼리다. 작성기가 `@TO(봇)` 을 미리 채우고 지우면 사람끼리. **첨부는 봇을 부른 글의 것만 읽고**, 나중에 "위 파일 봐 줘" 하면 대화 기록에서 첨부까지 끌어와 따라잡는다 | 물음 ② ③ |
| **R12** | **조종석 판 · 승인 카드 · 파일 판은 방 화면 오른쪽의 접이식 판.** member 는 접힘이 기본, admin 은 펼침이 기본. 승인 요청 · 답은 지금처럼 채팅 줄(🔒 · ✅ · ⛔)에도 남는다 | 물음 ④ |
| **R13** | **봇 없는 방은 첫 판에 없다.** 봇 배정 화면(`/api/rooms/:id/bots` · `/api/bots`)은 옮기지 않는다 | 물음 ⑤ |
| **R14** | **retro 진화는 그대로.** 굳는 자리는 과제 폴더(`house.md` · `templates/` · `analysis/methods/` · `journal/`)와 봇 폴더의 `find.log`(과제 폴더가 아니다 — D4 에서 바로잡음)이고 방 하나 = 과제 폴더 하나다. "카드 없는 첨부" 계측은 본방 첨부 기준으로 옮긴다 | 사람 5 |
| 순서 | 회사 PC 실증(W1)은 **지금 판(M4)** 으로 먼저 · 병행한다. v2 제작이 그것을 기다리지 않는다 | 물음 ⑥ |

## 무엇이 바뀌나 — 여섯
| | v1 | v2 | 왜 |
|---|---|---|---|
| 화면 | cockpit 이 새로 만든 채팅 · 조종석 · 파일 탭 | minidiscord 화면 이식 + 접이식 조종석 판 | 사람 첫 소감 "UI 가 별로" · 디스코드 디자인 계승 |
| 방 | 과제 = 방 둘(본방 · `/files`) — ADR-022 · F2 | 과제 = 방 하나. 첨부는 그 방에 | "디스코드처럼 자유롭게" |
| 봇에게 가는 글 | 본방 `@` 없음 → 봇에게 `to`(F3) | `@TO` · `@CC` 만(minidiscord 규칙) | 사람끼리 말할 자리 |
| 과제 열기 | `POST /api/projects` + 사람이 `setup.js` 따로 | `POST /api/rooms` 하나가 봇 폴더까지 만든다 | "방을 만들면 봇이 생긴다" |
| 따라잡기 | `fetch_history` 에 첨부 없음 · 방 둘 합쳐 읽어야 | `fetch_history` 결과에 첨부 경로 · 방 하나 | "위 파일 봐 줘" 가 R11 의 짝 |
| 하네스 | 도구 이름 · 경로만 바꿈 | 방 하나 판으로 11곳(`DIRECTION-v2.md` 2.3) — prodev PR 하나 · 새 ADR | R10 의 값 |

## 무엇이 안 바뀌나
SDK `query()` 로 세션을 띄우고 붙드는 방식 전부(ADR-001 · 002) · 저장소 둘(`chat.db` 표 여섯 그대로 · `cockpit.db`, ADR-003 · 004) · HTTP 길의 모양과 쿠키(ADR-005) · 권한 `default` + `allowedTools` 둘(ADR-006) · env 화이트리스트(ADR-007) · 큐 즉시 배달(W2r.1) · 승인 요청 단위(ADR-009) · 프레임워크 없음(ADR-010) · SSE 하나(ADR-012) · 압축 알림 system 글(ADR-014) · 재기동 resume · 세션 조작 다섯 길(8.3) · 봇의 세계(봉투 · `reply` · 훅 셋 · 스킬 15 · 도우미 6 · 과제 폴더 기억).

## 절차
1. **D0-v2 문서 관문** — cockpit 세션이 `docs/` 다섯을 고친다(`instructions/D0-v2.md`). meta 가 `scoring-cockpit-docs-v2.md` 로 센다.
2. **M5 제작** — 통과 뒤 지시. prodev 는 관문 사이에 worktree + PR(방 하나 판, 새 ADR).
3. **M5.M 관문** — 옛 대본 다섯의 v2 판(방 하나) + 새 대본 하나(사람끼리 글 · 따라잡기)를 meta 가 재생. 새 기준선.
4. **W4 실전.** W1(회사 PC)은 지금 판으로 병행.
