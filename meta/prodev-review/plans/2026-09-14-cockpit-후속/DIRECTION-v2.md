# 방향 v2 — minidiscord 와 cockpit 을 합친다 (사람 결정, 2026-09-14 저녁)

**상태: 사람이 방향을 말했다. 설계는 아직 안 열었다.** 이 문서는 사람 말을 옮기고, 지금 설계 · 하네스의 어디가 바뀌는지 사실로 짚고, 사람이 더 정할 물음을 고른다. cockpit 제작 세션에는 주지 않는다(설계가 굳은 뒤 지시문으로).
맥락: M1.M · W2r · M3.M 통과, M4.M 맥 조건부 통과 뒤. 사람이 이 맥에서 처음 화면을 눌러 보고("UI 가 별로다") 낸 방향이다.

## 1. 사람이 정한 것 (말을 옮김)
1. minidiscord 와 cockpit 의 **기능을 합친다.**
2. **minidiscord 의 UI 와 주요 기능(파일 첨부 · `@` 호출 등)은 그대로 두고, channels 만 Agent SDK 로 대체**한다.
3. **files 방은 뺀다.** 과제원이 디스코드처럼 자유롭게 자료를 올리고 받는 것이 훨씬 효율적이다.
4. **방을 만들면 prodev 기반으로 봇이 만들어지고, 그 방에 전용 봇이 들어간다.**
5. 각 봇이 **retro 로 기능을 갱신하며 진화하는 컨셉은 유지**한다.

## 2. 지금과 무엇이 다른가 — 사실

### 2.1 요구표(DESIGN 1절)에서 바뀌는 줄

### 2.2 화면과 API — 얼마나 겹치나 (오늘 grep)
cockpit 은 설계 때부터 minidiscord 의 API 모양과 DB 표 여섯을 그대로 뒀다(cockpit ADR-004 · 005). 그래서 minidiscord 의 `web/`(app.js 1231줄 · rich.js 214 · style.css 965 · index.html 117, 디자인 토큰 파일 하나)을 옮기는 값이 작다.

| minidiscord 화면이 부르는 길 (15) | cockpit 에 있나 |
|---|---|
| `/api/auth/login · logout · me` · `/api/rooms`(목록) · `/api/rooms/:id/messages`(커서 포함) · `/api/attachments/:id` | **있다** (같은 모양, 쿠키 `md_session` 같음) |
| `POST /api/rooms`(방 만들기) · `/api/rooms/:id/archive` | 없다 — cockpit 은 `POST /api/projects` 가 방 둘을 만든다. v2 의 "방 만들기 = 봇 생성" 이 바로 이 자리 |
| `/api/bots` · `/api/bots/:id` · `/api/rooms/:id/bots`(방에 봇 배정) | 없다 — v2 는 방마다 전용 봇 하나라 배정 화면이 필요 없을 수 있다(물음 ⑤) |
| `/api/rooms/:id/events`(방별 SSE) | cockpit 은 `/api/stream` 하나(ADR-012). 화면 쪽 한 함수를 고치면 된다 |

minidiscord 화면이 가진 것(CHANGELOG): 방 목록 사이드바 · 아바타 기둥 · 작성기 한 덩어리 · 계정 바(SPEC-WEBUI-001) · 본문 마크다운(WEBMD-001) · `@TO` · `@CC` 칩(WEBMD-002) · `@` 자동완성(ACNAV) · 이미지 붙여넣기 · 끌어놓기 · 썸네일(WEBATTACH-001) · UTC 표기 · 히스토리 끝까지 · SSE 백필. cockpit 화면은 이 중 마크다운 · 붙여넣기 · 끌어놓기 · 받기만 있고 나머지는 없다.

| 자리 | 지금 | v2 에서 |

| meta 대본 · 채점표 | R2 · R5 가 files 방에 올린다 | 대본을 본방으로 고쳐 다시 잰다(옛 판정과 비교 불가 — 새 기준선) |

### 2.4 "방을 만들면 봇이 생긴다" — 지금과의 거리
지금도 `POST /api/projects {name}` 이 봇 한 줄 · 방 둘 · 세션 한 줄을 만든다. 다만 **봇 폴더(과제 폴더 · `.claude/settings.json` · `settings.local.json` — 스킬 링크는 없다, CLI 가 prodev 뿌리에서 읽는다(D4 에서 바로잡음))는 사람이 prodev `setup.js --project` 를 따로 친다**(INSTALL 7번). v2 는 방 만들기 단추 하나가 그 걸음까지 하게 하는 것 — cockpit 이 `setup.js` 를 부르거나 같은 일을 한다. 이름 규칙(`prodev-<과제>-비서`) · 과제 폴더 자리는 그대로.

### 2.5 retro 진화 — 유지되는가
유지된다. 진화의 자리는 방이 아니라 **과제 폴더**(`house.md` 50줄 · `templates/` · `analysis/methods/` · `journal/` · 봇 폴더 `find.log`)이고, 방 하나 = 과제 폴더 하나면 그대로다(ADR-031~037). 바뀌는 것 하나: retro · weekly 가 세는 "카드 없는 첨부" 가 본방 첨부 기준이 된다. 그리고 `retro` 는 여전히 사람이 부른다(cron 없음) — "알아서 진화" 는 후속 README 3.5-1 의 제동 논의 그대로 남는다.

### 2.6 후속 README 와 맞물리는 것
- 방 하나가 되면 **3.2(본방에서 봇 빼고 사람끼리)** 를 같이 정해야 한다. minidiscord 규칙(`@` 없으면 봇에게 안 감, 안 A)이 자연스럽다 — 사람이 "디스코드처럼 자유롭게" 라 했다.
- 그러면 **3.3 따라잡기**("위 파일 봐 줘")가 필수가 된다. 봇이 안 본 첨부를 나중에 들여야 하기 때문이다.
- **3.5-2**(과제원 화면은 채팅 기본, 조종석은 접기)가 물음 ④ 의 답 후보다.

| # | 물음 | meta 추천 |
|---|---|---|
| ① | 기반 저장소: (가) cockpit 에 minidiscord `web/` 을 옮기고 길 넷을 더한다 / (나) minidiscord 서버에 세션 관리자 · 승인 중계 · 사건 · resume 을 옮긴다 | **(가)**. API 가 이미 같은 모양이고, 세션 쪽(시험 158 · 스모크 다섯 · 관문 넷)이 cockpit 에 있다. (나)는 TS 저장소로 그것을 다시 쓰는 일 |
| ② | 방 하나에서 봇에게 가는 글: minidiscord 처럼 `@TO(봇)` 만 / 지금처럼 전부 | **`@TO` 만** (후속 3.2 안 A). 입력창이 `@TO(봇)` 을 미리 채우고, 지우면 사람끼리 |
| ③ | 첨부를 봇이 언제 읽나: `@TO` 로 부른 글의 첨부만 + "위 파일 봐 줘"(따라잡기) / 올라오는 족족 | **부른 것만 + 따라잡기**. 족족 읽으면 문맥과 값이 새고 "한 턴에 들이기 한 건" 지침과 부딪힌다 |
| ④ | 조종석 판 · 승인 카드 · 파일 판의 자리 | 방 화면 오른쪽 **접이식 판**(member 는 접힘이 기본, admin 은 펼침). 승인 카드는 지금처럼 채팅 줄에도 |

| ⑥ | 순서: 회사 PC W1 실증(로그인 · SDK · 권한)을 지금 판으로 먼저 하나, 개편 뒤에 하나 | **먼저**. UI 와 무관한 위험(회사 계정 · 프록시 · 윈도우 env)이 더 크고, 개편 중에도 병행된다 |

## 4. 절차 (meta 규칙 그대로)
1. 사람이 3절에 답한다.
2. meta 가 `AS-IS-TO-BE-v2.md` + DESIGN 개정 절(R9~) + 예측(숫자)을 쓴다. 옛 대본 다섯을 방 하나 판으로 고친다(새 기준선).
3. cockpit 새 회차 **M5**(minidiscord 화면 이식 · 방 하나 · 방 만들기 = 봇 생성 · 접이식 조종석) + prodev PR(방 하나 판, 새 ADR) — 관문 사이에 worktree + PR.
4. 재생 관문 W2v2(대본 다섯) → 실전 W4.
설계 문서 셋(cockpit PRD · ARCHITECTURE · TASKS)의 개정은 cockpit 세션이 하되, 요구와 판정 기준은 meta 가 준다.
