# 지금(As-Is) → 앞으로(To-Be) — 한 장으로 (2026-09-14)

`DESIGN.md` 를 읽기 전에 보는 요약이다. 무엇이 왜 바뀌고, 무엇은 안 바뀌는지만 적는다.

## 한 줄

**지금은 채팅 서버(minidiscord)가 채널 플러그인으로 봇 세션을 깨웠다. 회사가 그 통로(channels)를 막았다. 앞으로는 웹 앱 하나(조종석)가 봇 세션을 직접 띄우고 붙들며, 사람은 그 웹 앱에 브라우저로 들어온다.** 봇이 보는 세계는 그대로다.

## 그림

```
지금 (As-Is)                                     앞으로 (To-Be)

사람 ─브라우저─▶ minidiscord 서버                 사람 ─브라우저─▶ 조종석 서버 (새로 만든다)
                  │ 채널 플러그인 (channels) ✗ 회사가 막음      │ Agent SDK query() — 세션을 직접 띄운다
                  ▼                                            ▼
              Claude Code 세션 (prodev 봇)                Claude Code 세션 (prodev 봇, 그대로)
                  │ reply 도구 · 훅 셋 · 스킬 15                │ reply 도구 · 훅 셋 · 스킬 15 (그대로)
                  ▼                                            ▼
              과제 폴더 (기억은 여기)                      과제 폴더 (기억은 여기, 그대로)
```

## 무엇이 바뀌나 — 핵심 여섯

| | 지금 | 앞으로 | 왜 |
|---|---|---|---|
| **봇을 깨우는 길** | 채팅 서버 → 채널 플러그인 → 세션 | 조종석 서버가 SDK 로 세션을 띄우고 글을 넣는다 | channels 가 막혔다. headless · SDK 는 회사 PC 에서 되는 것을 확인했다 |
| **세션의 수명** | 터미널에서 사람이 `claude …` 를 쳐서 켠다 | 조종석이 과제마다 세션 하나를 살려 둔다. 문맥 · 압축 · 훅 · 도우미가 실제 Claude Code 와 같다 | 단발 요청형은 기각했다(사람 결정, R0) |
| **사람이 보는 화면** | 채팅방 둘 | 채팅 + **조종석 판**(도구 호출 · 도우미 진행 · 승인 카드 · 값 · 문맥 사용률) + 파일 판 | 봇이 일하는 과정을 보고 승인할 수 있어야 한다 |
| **승인** | 방에 `yes <id>` 를 친다 (채널 릴레이) | admin(PL) 브라우저에 카드가 뜨고 버튼으로 답한다. 과제원은 못 누른다 | 역할 둘. 승인 기록은 본방 system 글로도 남는다 |
| **채팅 서버** | minidiscord (자기 저장소) | **없앤다.** 조종석이 방 둘 · 글 · 첨부 · 계정을 직접 가진다 | 사람이 "확장" 이 아니라 "대체" 를 택했다 |
| **저장소** | minidiscord SQLite 하나 | `chat.db`(minidiscord 표 여섯 **그대로**, 봇이 읽기만) + `cockpit.db`(계정 · 세션 · 승인, 봇이 못 봄) | 하네스 스크립트가 DB 를 직접 읽는다 → 열 이름을 그대로 두면 한 줄도 안 고친다. 계정 해시는 봇이 못 보게 가른다 |

## 무엇이 안 바뀌나 — 봇의 세계

- 방 둘(본방 · files) · 봉투(`@TO` · `@CC`) · `reply` 에 언제나 `chat_id`.
- 비서 지침 열한 줄 · 스킬 열다섯 · 훅 셋(켤 때 싣기 · 압축 전 인수인계 · 보내기 전 검사) · 도우미 여섯 · 스크립트 열.
- 기억은 세션이 아니라 **과제 폴더의 파일**. 꺼졌다 켜도 파일에서 되살아난다.
- 허용 목록 22건. 목록 안은 승인 없이, 밖은 사람에게.

바뀌는 것은 이름과 경로뿐이다: 도구 이름(`mcp__minidiscord-channel__reply` → `mcp__cockpit__reply`, 서명 같음) · DB 경로 · 업로드 폴더 · 기동 방식. prodev 저장소에는 PR 하나로 들어간다.

## 왜 이 길인가 — 다른 길 셋을 왜 안 택했나

| 길 | 왜 아닌가 |
|---|---|
| 터미널을 그대로 웹에 띄우기 (ttyd 류) | 가장 단순하고 하네스는 100% 그대로다. 그러나 화면 글자만 오가서 **누가 말했는지 · 역할별 승인 · 대화 저장소**가 구조적으로 안 생긴다. "다른 사람도 들어온다" 는 목표에 못 닿는다 |
| headless CLI 를 직접 조립 (stream-json) | 되지만 승인 경로가 문서에 없는 플래그에 기댄다. SDK 는 같은 것을 타입 있는 공식 API 로 준다 |
| 공식 Remote Control | 기능은 가장 가깝지만 대화 기록이 Anthropic 서버에 저장되고 조직이 끌 수 있다. 사내망 자체 호스팅 요구와 맞지 않는다 |

## 이미 확인한 것 (이 맥에서 직접 돌렸다 — `spike/RESULTS.md`)

- SDK 로 띄운 세션에 prodev 하네스가 그대로 실린다. 프로세스 안 `reply` 도구를 봇이 부르고, 그 도구에 pre-reply 훅이 걸린다.
- 세션 하나를 살려 둔 채 말 셋을 넣고 중간에 `/compact` 를 넣으면 압축 앞뒤 훅이 돈다.
- 권한 판정은 SDK 세션과 headless CLI 가 같다. 허용 목록 안은 승인 없이, 밖은 콜백으로 온다.
- API 키 없이 claude.ai 로그인으로 돈다(이 맥은 Max 계정). **회사 계정(Team/Enterprise)에서는 아직 안 밟았다 — 첫 관문 W1.**
