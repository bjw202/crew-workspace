# meta → cockpit 지시 · M4 (2026-09-14 20:25, M3.M 통과 뒤)

cockpit 세션이 읽는 지시문. 앞 단계는 M3(마지막 커밋 c525b51) + prodev PR #18. 판정 근거는 meta 가 쥔다 — 여기에는 결정과 할 일만.

## 1. M3.M 결과 (요지)
**통과.** cockpit 자체 열 칸 전부 ○(굵은 넷 포함), R5 압축 · 재기동 8/9(옛 관문 6/9 이상), 승인 재측정 R2+R4 합 **4**(W2r 31, 예측 ≤ 10). meta 가 사본에서 R2 → R4 → R5 → 점검 한 걸음을 sonnet-5 로 재생했고, R5 의 손 걸음 셋(압축 · 끄기 · 켜기)은 ARCHITECTURE 8.3 의 admin API 로 대신했다 — 표에 적힌 "끝났다고 볼 것" 만으로 충분했다. 재기동 뒤 놓친 글 다섯이 한 묶음으로 재배달돼 5/5 처리, 켜짐 → 첫 답 2분 15초.

빗나간 하나(5-9)는 봇이 v2 파일을 카드의 `files:` 에 안 붙인 것 — prodev 스킬 쪽, cockpit 아님.

## 2. 새 질문 답
- **N11 값 바닥 — 인정.** meta 실측: `result` 의 `total_cost_usd` 는 같은 CLI 프로세스 안에서 누적(0.37 → … → 3.77, 사이의 `init` 사건은 턴마다의 system init 이지 프로세스 교체가 아님), stop → start 뒤 0 부터(0.53 → 1.69). `agent_sessions.cost_usd` = 3.77 + 1.69 = 5.46 로 맞았다. W2r.2 의 뜻("더하지 않는다")은 프로세스 안의 이야기이고, 프로세스가 바뀔 때만 바닥을 올리는 것은 그 뜻과 어긋나지 않는다. 그대로 두고 **ARCHITECTURE 5.3 에 한 줄** 적어라: "재기동 뒤 값 = 정지 시점 값(바닥) + 새 프로세스 누적". 덧: 조종석 값 $5.46 과 meta 의 표준단가 계측 $7.99(도우미 호출 32 포함)가 다르다. SDK `total_cost_usd` 가 도우미(서브에이전트) 값을 싣는지 확인해 같은 줄에 적어라(코드 고침 아님, 문서).
- **N12 — PR #18 은 meta 검수 통과(사본 142 · 18 · 0 실패 · 재생에서 find.log 가 스크래치 봇 폴더에 · curl 0 · 히어독 0). 머지는 사람.** 머지되기 전까지 `COCKPIT_PRODEV_DIR` 은 `../prodev-wt-cockpit`(가지 `cockpit-m3`) 그대로다. 머지되면 meta 가 알린다.
- **N13 — 화면은 사람이 회사 PC 에 설치할 때(W1 · M4.2 문서로) 처음 눌러 본다.** M4 에 브라우저 스모크를 넣지 않는다. 대신 M4.2 설치 문서의 마지막 걸음을 "브라우저로 열어 과제 탭 · 조종석 판 · 파일 판 셋을 눌러 보고 보이는 것을 적는다" 로 둔다 — 사람이 그 걸음의 결과를 meta 에 준다.

## 3. M3.M 에서 본 것 (고침 아님 · 문서에만)
- `tool_use` 입력 요약이 200자 + 줄임표 = **201자** 였다. 시험 이름은 "200자" 다. as-built 2.3 에 "200자 뒤 줄임표 한 자" 라고 적어 두면 다음 채점이 헛갈리지 않는다. 자르는 길이를 바꾸지 마라(관문 사이에 고칠 것이 아니다 — 뜻이 맞다).
- 파일 판의 과제 밖 경로는 설계대로 404 였다(meta 예측이 403 이라 적은 것은 meta 의 실수).
- 압축 요청이 `queued:true` 로 3분 36초 뒤 들어갔고 방 글 둘(#35 정리 중 · #36 끝)이 남았다 — 설계대로.
