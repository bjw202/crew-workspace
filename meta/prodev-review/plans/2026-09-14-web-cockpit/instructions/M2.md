## 4. M2 진행 규칙 (M1 과 같음 + 셋)
공통: 태스크 단위 커밋(첫 줄에 태스크 번호) · `npm test` 는 서버 · SDK · 네트워크 없이 · 스모크는 스크래치 + haiku + `prodev/bots` 금지 · prodev · minidiscord 본 체크아웃은 읽기만 · meta 의 예측 · 채점표 · fixtures · runs 는 읽지 않음 · 화면은 프레임워크 · 빌드 · CDN 없이.

1. **M2.M 은 곧 W2 관문.** meta 가 옛 대본 다섯(R1~R5)을 `prodev/scripts/replay.js` 로 cockpit 서버에 재생한다. 그래서 M2 끝에 다음이 되어야 한다:
   - `node bin/cockpit.js serve --config <설정>` 으로 서버가 뜬다.
   - `node bin/cockpit.js session-token <이름>` 이 `md_session` 값을 낸다.
   - `GET /api/rooms` · `POST /api/rooms/:id/messages`(multipart 만) · `GET /api/rooms/:id/messages?after=` 가 minidiscord 와 같은 응답 모양이다.
   - `open-project` 가 방 둘(`prodev-<과제>` · `prodev-<과제>/files`)을 만든다.
   - replay.js 의 계약은 `prodev/scripts/replay.js:18-25, 85-124` 와 `prodev/test/server/replay.test.js` 에 있다. **그 가짜 서버 시험이 cockpit 서버에 대해서도 초록이면** 된다 — 계약 시험으로 넣는다.
2. 승인 카드(M2.4)는 SDK 가 주는 `title · displayName · description · suggestions · suppressAlwaysAllowRule · defaultToNo` 를 그대로 쓴다. `smoke/m2-approval.mjs` 는 admin 역할로 거부 한 번 · 허용 한 번 · "이번 세션 허용" 한 번(같은 도구 재요청이 0 인지)까지.
3. minidiscord `web/markdown.js` 사본은 출처 핀을 머리에.
